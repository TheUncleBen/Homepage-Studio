# Filebrowser

File manager. Available, Used, Total.

Integration · type `filebrowser` · [Homepage documentation](https://gethomepage.dev/widgets/services/filebrowser/)

[All widgets](README.md)

## What it needs

Learn more about [Filebrowser](https://filebrowser.org).

If you are using [Proxy header authentication](https://filebrowser.org/configuration/authentication-method#proxy-header) you have to set `authHeader` and `username`.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://filebrowserhostorip:port`. |
| Username | `username` | Text | Example: `username`. |
| Password | `password` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Auth Header | `authHeader` | Text | Example: `X-My-Header`. |
| Visible fields | `fields` | List | Choices: `available`, `used`, `total`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| Password | `homepage_filebrowser_password` | `HOMEPAGE_FILE_FILEBROWSER_PASSWORD: /run/secrets/homepage_filebrowser_password` | `{{HOMEPAGE_FILE_FILEBROWSER_PASSWORD}}` |

For a second Filebrowser with different credentials, add a suffix such as `_2` to each name.

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: filebrowser
  url: http://filebrowserhostorip:port
  username: username
  password: password
  authHeader: X-My-Header # If using Proxy header authentication
```
