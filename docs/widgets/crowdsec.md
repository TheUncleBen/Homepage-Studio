# CrowdSec

## What it needs

Learn more about [Crowdsec](https://crowdsec.net).

See the [crowdsec docs](https://docs.crowdsec.net/docs/local_api/intro/#machines) for information about registering a machine, in most instances you can use the default credentials (`/etc/crowdsec/local_api_credentials.yaml`).

> **Note**
>
> `alerts` counts alerts raised by your own engine in the last 24 hours. Alerts originating from the CrowdSec community blocklist are excluded.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://crowdsechostorip:port`. |
| Username | `username` | Text | Example: `localhost`. |
| Password | `password` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Visible fields | `fields` | List | Choices: `alerts`, `bans`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| Password | `homepage_crowdsec_password` | `HOMEPAGE_FILE_CROWDSEC_PASSWORD: /run/secrets/homepage_crowdsec_password` | `{{HOMEPAGE_FILE_CROWDSEC_PASSWORD}}` |

For a second CrowdSec with different credentials, add a suffix such as `_2` to each name.
