## What it needs

Learn more about [Unifi Controller](https://ui.com/).

_(Find the Unifi Controller information widget [here](https://gethomepage.dev/widgets/info/unifi_controller/))_

You can display general connectivity status from your Unifi (Network) Controller.

> **Warning**
>
> When authenticating you will want to use a local account that has at least read privileges.

An optional 'site' parameter can be supplied, if it is not the widget will use the default site for the controller.

> **Note**
>
> If you enter e.g. incorrect credentials and receive an "API Error", you may need to recreate the container or restart the service to clear the cache.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `https://unifi.host.or.ip:port`. |
| Site | `site` | Text | Example: `Site Name`. |
| Username | `username` | Text | Example: `user`. |
| Password | `password` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| API key | `key` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Visible fields | `fields` | List | Choices: `uptime`, `wan`, `lan`, `lan_users`, `lan_devices`, `wlan`, `wlan_users`, `wlan_devices`. The widget shows them in the order you list them. Leave unset for its usual fields. |

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: unifi
  url: https://unifi.host.or.ip:port
  site: Site Name # optional
  username: user
  password: pass
  key: unifiapikey # required if using API key instead of username/password
```
