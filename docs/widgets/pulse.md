## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://pulse.host.or.ip:7655`. |
| API key | `key` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Pulse version | `version` | Number | A choice in the dialog: Before Pulse 6 (`1`, the default when left out), Pulse 6 (`2`). Which Pulse you run, so the widget uses the matching API. Homepage can't detect it. |
| Visible fields | `fields` | List | Choices: `nodes`, `vms`, `lxcs`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| API key | `homepage_pulse_key` | `HOMEPAGE_FILE_PULSE_KEY: /run/secrets/homepage_pulse_key` | `{{HOMEPAGE_FILE_PULSE_KEY}}` |

For a second Pulse with different credentials, add a suffix such as `_2` to each name.

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: pulse
  url: http://pulse.host.or.ip:7655
  key: your-api-token # `monitoring:read` scope is required
  version: 2 # required for Pulse v6, defaults to 1
  fields: ["nodes", "vms", "lxcs"] # optional
```
