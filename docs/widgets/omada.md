# Omada

Network controller. Connected APs, Active devices, Alerts, Connected gateways, Connected switches.

Integration · type `omada` · [Homepage documentation](https://gethomepage.dev/widgets/services/omada/)

## What it needs

The widget supports controller versions 3, 4, 5 and 6.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://omada.host.or.ip:port`. |
| Username | `username` | Text | Example: `username`. |
| Password | `password` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Site | `site` | Text | Example: `sitename`. |
| Visible fields | `fields` | List | Choices: `connectedAp`, `activeUser`, `alerts`, `connectedGateways`, `connectedSwitches`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| Password | `homepage_omada_password` | `HOMEPAGE_FILE_OMADA_PASSWORD: /run/secrets/homepage_omada_password` | `{{HOMEPAGE_FILE_OMADA_PASSWORD}}` |

For a second Omada with different credentials, add a suffix such as `_2` to each name.
