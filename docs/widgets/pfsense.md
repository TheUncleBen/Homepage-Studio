# pfSense

Firewall. Load Avg, Mem Usage, Temp, WAN Status, WAN IP, Disk Usage.

## What it needs

Learn more about [pfSense](https://github.com/pfsense/pfsense).

This widget requires the installation of the [pfsense-api](https://github.com/jaredhendrickson13/pfsense-api) which is a 3rd party package for pfSense routers.

Once pfSense API is installed, you can set the API to be read-only in System > API > Settings.

There are two currently supported authentication modes: 'Local Database' and 'API Key' (v2) / 'API Token' (v1). For 'Local Database', use `username` and `password` with the credentials of an admin user. The specifics of using the API key / token depend on the version of the pfSense API, see the config examples below. Do not use both headers and username / password.

The interface to monitor is defined by updating the `wan` parameter. It should be referenced as it is shown under Interfaces > Assignments in pfSense.

Load is returned instead of cpu utilization. This is a limitation in the pfSense API due to the complexity of this calculation. This may become available in future versions.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://pfsense.host.or.ip:port`. |
| Username | `username` | Text | Example: `user`. |
| Password | `password` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Request headers | `headers` | Settings (name: value) |  |
| WAN interface | `wan` | Text | Example: `igb0`. |
| pfSense REST API version | `version` | Number | A choice in the dialog: API v1 (`1`, the default when left out), API v2 (`2`). Which version of the pfSense REST API package you run, so the widget uses the matching API. Homepage can't detect it. Version 1 uses an API token and version 2 an API key; see the setup guide. |
| Visible fields | `fields` | List | Choices: `load`, `memory`, `temp`, `wanStatus`, `wanIP`, `disk`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| Password | `homepage_pfsense_password` | `HOMEPAGE_FILE_PFSENSE_PASSWORD: /run/secrets/homepage_pfsense_password` | `{{HOMEPAGE_FILE_PFSENSE_PASSWORD}}` |
| API key (v2), as the X-API-Key header | `homepage_pfsense_api_key` | `HOMEPAGE_FILE_PFSENSE_API_KEY: /run/secrets/homepage_pfsense_api_key` | `{{HOMEPAGE_FILE_PFSENSE_API_KEY}}` |

For a second pfSense with different credentials, add a suffix such as `_2` to each name.

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: pfsense
  url: http://pfsense.host.or.ip:port
  username: user # optional, or API key
  password: pass # optional, or API key
  headers: # optional, or username/password
    X-API-Key: key
  wan: igb0
  version: 2 # optional, defaults to 1 for api v1
  fields: ["load", "memory", "temp", "wanStatus"] # optional
```
