## What it needs

Learn more about [NetAlertX](https://github.com/jokob-sk/NetAlertX).

_Note that the project was renamed from PiAlert to NetAlertX._

Provide the `API_TOKEN` (f.k.a. `SYNC_api_token`) as the `key` in your config.

| NetAlertX Version | Homepage Widget Version |
| --- | --- |
| < v26.1.17 | 1 (default) |
| > v26.1.17 | 2 |

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://ip:port`. |
| API key | `key` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| NetAlertX version | `version` | Number | A choice in the dialog: Before 26.1.17 (`1`, the default when left out), After 26.1.17 (`2`). Which NetAlertX you run, so the widget uses the matching API. Homepage can't detect it. With version 2, the address is the NetAlertX backend port. |
| Visible fields | `fields` | List | Choices: `total`, `connected`, `new_devices`, `down_alerts`. The widget shows them in the order you list them. Leave unset for its usual fields. |

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: netalertx
  url: http://ip:port # use backend port for widget version 2+
  key: yournetalertxapitoken
  version: 2 # optional, default is 1
```
