# Healthchecks

Cron job monitoring. Status, Last Ping.

Integration · type `healthchecks` · [Homepage documentation](https://gethomepage.dev/widgets/services/healthchecks/)

[All widgets](README.md)

## What it needs

Learn more about [Health Checks](https://github.com/healthchecks/healthchecks).

Specify a single check by including the `uuid` field or show the total 'up' and 'down' for all checks by leaving off the `uuid` field.

To use the Health Checks widget, you first need to generate an API key.

1. In your project, go to project Settings on the navigation bar.
2. Click on API key (read-only) and then click _Create_.
3. Copy the API key that is generated for you.

## Settings

What the widget dialog shows. Anything else the widget accepts goes in the dialog's YAML view.

| Setting | YAML key | Type | Notes |
| --- | --- | --- | --- |
| Service URL | `url` | Text | Example: `http://healthchecks.host.or.ip:port`. |
| API key | `key` | Text | Secret: hidden while you type. Prefer a `{{HOMEPAGE_VAR_…}}` or `{{HOMEPAGE_FILE_…}}` reference. |
| Uuid | `uuid` | Text | Example: `<CHECK_UUID>`. |
| Visible fields | `fields` | List | Choices: `status`, `last_ping`. Leave unset for its usual fields. |

## Keeping its secrets out of the files

Store each as a Docker secret ([DEPLOY.md](../DEPLOY.md#widget-api-keys-as-docker-secrets)) with exactly these names:

| Setting | Docker secret | Environment variable | Enter in the setting |
| --- | --- | --- | --- |
| API key | `homepage_healthchecks_key` | `HOMEPAGE_FILE_HEALTHCHECKS_KEY: /run/secrets/homepage_healthchecks_key` | `{{HOMEPAGE_FILE_HEALTHCHECKS_KEY}}` |

For a second Healthchecks with different credentials, add a suffix such as `_2` to each name.

## Examples

From Homepage's documentation. Values are examples, not defaults.

```yaml
widget:
  type: healthchecks
  url: http://healthchecks.host.or.ip:port
  key: <YOUR_API_KEY>
  uuid: <CHECK_UUID> # optional, if not included total statistics for all checks is shown
```
